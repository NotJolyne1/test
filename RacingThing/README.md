# Racing Thing

Low-poly racing with 7 summer tracks, loops, jumps and boost pads. You can play time trials on your own, or race up to 8 people online using the RelayNetworking server.

Made in Unity **2022.3.62f3** with the Built-in render pipeline, so it runs on school laptops.

## Opening it

1. Extract the zip. You get a `RacingThing` folder with `Assets`, `Packages` and `ProjectSettings` in it.
2. In Unity Hub, go to **Add > Add project from disk** and pick that folder.
3. Open it and press **Play**. The game scene opens on its own the first time.

Build an exe with **Racing Thing > Build Windows**. It goes to `Builds/Windows/`.

## Playing online

You run the RelayNetworking server yourself (it isn't in this project). Start it first, then:

1. Everyone opens the game and clicks **Multiplayer**.
2. Put the server's IP in the **Server** box. Use `127.0.0.1` if the game and the server are on the same PC. Friends on other PCs use that PC's IP address, and port 7777 (UDP) has to be open. If the server uses another port, write it as `ip:port`.
3. One person clicks **Host a game**. They get a room code, like `K7QPA`.
4. Everyone else types the code in and clicks **Join**.
5. In the lobby the host picks the track and can kick people, or hand the host role to someone else. Everyone can change their car colour and chat.
6. The host clicks **Start race**. Everyone loads the track, there's a 3-2-1 countdown, and then it's a race. The first one to the finish wins. After the first finish, everyone else has 30 seconds.
7. The results show everyone's time. When the host clicks **Back to lobby** (or after 45 seconds), everyone goes back for the next race.

The cars go through each other, like ghosts, so nobody gets knocked off the track. Press Esc for the menu. It doesn't pause the game, because the others are still racing.

Testing on your own: you can start a race with just one person in the room. To see two cars, build an exe and run it next to the editor. Both can host or join on `127.0.0.1`.

## Controls

| | |
|---|---|
| W / Up | Accelerate |
| S / Down | Brake and reverse |
| A D / Left Right | Steer |
| Space / Shift | Drift |
| Enter | Go back to the last checkpoint, keeping your speed |
| R | Restart (online: last checkpoint) |
| H | Horn (online) |
| C | Camera |
| Esc | Pause (online: menu) |

In time trials the timer starts as soon as you press a key.

## Tracks

Tracks are text files in `Assets/RacingThing/Resources/Tracks`. Each line is one piece, and the pieces snap together on a 10 m grid:

```
name: My Track
theme: meadow        # meadow, coast, forest, lake, canyon, sunset, tropic
difficulty: 2

start
forward 3            # 3 tiles straight
right 2              # 90 degree turn, size 1-4 (bigger = wider)
left 3 bank          # banked turn
right 2 up=1         # turn that climbs one level (2.5 m)
up 2                 # climb 2 levels over 2 tiles ("steep" doubles it)
down 2
boost 2              # boost pad, 2 tiles long
cp                   # checkpoint
ramp                 # small kicker
gap 3 drop=1         # 3 tiles of air, landing one level lower
loop                 # full loop, comes out one tile to the right ("loop left" for the other way)
finish
```

Check a track after editing it. The checker reports overlapping pieces, tests the jumps at different speeds, and draws a little map:

```
python3 Tools/track_tool.py Assets/RacingThing/Resources/Tracks maps
```

## Sounds

The sounds in `Resources/Audio` are generated by `Tools/make_sounds.py` (it needs numpy and scipy). You can also drop in your own .wav files with the same names.

## Code

- `Core/Game.cs`: startup, menus, loading tracks
- `Race/Race.cs`: timing, checkpoints, respawning, ghosts, and the online start and finish
- `Car/CarController.cs`: driving physics. The numbers at the top are the ones to tweak.
- `Track/TrackPath.cs`: turns the track file into a 3D path
- `World/`: road, terrain and scenery meshes, all generated at load time
- `Online/`: multiplayer (see below)

## How the multiplayer uses RelayNetworking

The client parts of RelayNetworking are in `Assets/RelayNetworking`: `Scripts` holds the Unity scripts, and `Client` and `Common` hold the library. LiteNetLib 2.1.4, which RelayNetworking needs, is in `Assets/Plugins/LiteNetLib` (MIT licence). The server isn't included, because you run that.

| Feature | Used for |
|---|---|
| App id `racing-thing`, anonymous sign-in | your name is your username |
| Room name | the room code |
| Room leader | the host. If the host leaves, the server picks a new one and the race carries on. |
| Room properties | track, race state (lobby / loading / race / results), who's racing, the GO time, results |
| Player properties | car colour, and which race you've finished loading |
| Server clock (`RelayNetwork.ServerTime`) | everyone's countdown hits GO at the same moment |
| Player objects (`NetworkManager` player prefab = `Prefabs/NetCar.prefab`) | every player's car |
| `NetworkTransform` | sends your car's position, 20 times a second |
| `[NetworkVariable]` | checkpoints passed, for the live race order |
| `[RelayRpc]` | the horn |
| Events | chat (code 10) and finish times (code 11) |
| `DropConnection` | kicking |
| `TransferLeader` | the "Make host" button |

The **Network** object in `Scenes/Main.unity` holds `NetworkManager` and `NetworkPrefabRegistry`. If it ever gets broken, **Racing Thing > Fix Project Setup** puts it back.

Things I changed or worked around in RelayNetworking:

- `Scripts/GUI/NetworkUI.cs` (the test window) uses a `TestNetworkVariables` script that wasn't in the zip, so it stopped everything from compiling. It's wrapped in `#if RELAY_TEST_UI` now. Add that define, and the missing script, if you want it back.
- When someone joins, the server only sends them the other players' names, not their custom properties. So every player sends their car colour again whenever someone new joins. Sending custom properties in `PlayerSync` on the server would fix this properly.
- `NetworkSpawner.DestroyAll()` takes the main camera out of its parent when you leave a room. The game's camera is a top-level object, so that doesn't matter here.
- The server returns no error when a room name is already taken, so creating a room just never finishes. The game waits 8 seconds and tries a new code (up to 3 times).
- On the server, `RpcRegistry` keeps RPCs by behaviour id + method id across all objects and apps. That's fine for this game because every car has the same single RPC, but two different scripts with RPCs at the same ids would clash.
